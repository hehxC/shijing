# 任务五验收：用户级限流和生成额度

## 实现范围

- 登录：每 IP 每分钟 10 次；
- 注册：每 IP 每小时 5 次；
- 普通聊天：每用户每分钟 10 次；
- 视觉分析：每用户每分钟 3 次；
- 图片上传：每用户每分钟 10 次；
- 效果图生成：每用户并发 1 个、每天 10 次；
- 效果图请求支持 `Idempotency-Key`，正在处理时拒绝重复执行，完成后重放结果；
- HTTP 429 返回 `Retry-After` 和 `allowed`、`remaining`、`retry_after`、`reason`；
- 前端显示服务端限流原因和建议等待时间。

所有阈值均可通过 README 中列出的环境变量调整。当前实现是线程安全的单实例
进程内存储；多实例生产部署前应通过 FastAPI 的 `get_rate_limit_service` 依赖替换为
共享 Redis 实现。

## 验收结果

专项测试：

```text
Ran 14 tests
OK
```

全量回归：

```text
Ran 82 tests
OK
```

已验证：

1. 第 11 次效果图生成返回 429，且不创建用户消息、不调用模型；
2. 不同用户的每日额度相互隔离；
3. 同用户已有生成任务时，新生成请求不会调用模型；
4. 相同幂等请求完成后直接重放，不产生第二次模型调用；
5. 失败请求使用原幂等键重试时不会再次扣除每日额度；
6. 数据库在流式响应前失败时会释放并发名额；
7. 登录、注册和上传超限均在数据库或存储操作前拒绝；
8. 普通聊天与视觉分析使用独立的用户级窗口；
9. 前端发送 `Idempotency-Key`，并展示 429 的具体原因和 `Retry-After`。

测试全部使用内存替身，没有调用真实模型、向量库或图片服务。
